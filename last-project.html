Play-Smart Esports Analytics

My graduation project at The Hive, the esports lab behind the Breda Guardians.

Migrating Play-Smart to a version-controlled deployment workflow

Play-Smart is a multi-modal esports analytics toolkit built at The Hive for the Breda Guardians, in collaboration with Tilburg University and the University of Twente. It collects and processes data from semi-professional VALORANT players - Tobii eye tracking, OpenFace facial action units, keyboard and mouse input, and game recordings - and surfaces it through an analytics dashboard for coaches and researchers.

For my graduation project I joined the project as Research Manager. The toolkit used to be moved between machines and institutions by hand on USB drives, which made it hard to reproduce, share and maintain. My work focused on migrating Play-Smart to a version-controlled, automated deployment workflow so the toolkit can be shared and run across all three partner institutions.

I containerised the toolkit into a multi-service Docker stack (frontend, backend, data pipeline, YOLOv11 inference and SFTP) running on a self-hosted Ubuntu server. A GitHub Actions pipeline lints, builds and publishes the service images to Docker Hub, and a self-hosted runner deploys them to the server automatically. A custom Git branching strategy keeps the BUas, Tilburg and Twente forks in sync. The diagram above shows how the pieces fit together.

To check that the new workflow is an actual improvement and not just a different way of working, I evaluated the migration through a within-subjects usability study that combines the TAM, DORA and SPACE frameworks.

Automated CI/CD

A GitHub Actions pipeline runs on every push to main: Ruff linting, container image builds, and a push to the playsmartbuas registry on Docker Hub. A self-hosted runner then deploys the updated stack to the server, replacing the manual USB steps.

Containerised stack

Every part of the toolkit - frontend, backend, data pipeline, inference and file transfer - runs as its own container, with scheduling handled by supercronic. This makes the toolkit reproducible and straightforward to bring up on a new machine.

Shared branching strategy

A hybrid Git Flow and GitHub Flow branching model lets BUas, Tilburg and Twente work from their own forks while keeping a single shared upstream, so changes can move between institutions in a controlled, traceable way.
