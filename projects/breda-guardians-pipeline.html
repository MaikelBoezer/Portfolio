Work / The Hive

Turning esports sensor data into a dashboard, from nothing

Building the first data collection, storage and automation pipeline for the Breda Guardians esports analytics project - before there was anything to build on top of.

RoleData Engineer & Analytics Translator
OrganisationThe Hive, Breda Guardians (BUas)
Period2024
TeamFirst cohort on a multi-year project

Original data flow: four capture sources feed a Python collection script, which pushes bulk files to SFTP and structured data to PostgreSQL — both running in one Docker container — for the dashboard to read from.

The problem

This was a multi-year project for Applied Data Science & AI students, and I was part of the first cohort - which meant there was nothing to inherit. No pipeline, no storage, no dashboard, and no working relationship yet with the coaches who'd eventually use it. The original brief was to build an AI coach that could give VALORANT players feedback on their performance.

Early on it became clear that an AI coach wasn't realistic in the time we had. Rather than force it and risk shipping nothing that worked, we scoped down to laying the groundwork the next cohorts would actually need: reliable data collection, sensible storage, and a dashboard that showed what had been captured so far.

What I built

We collected four modalities: keyboard and mouse input through a Python script, gaze data from a Tobii eye tracker, facial expressions through a webcam feed processed with OpenFace, and full match video through OBS.

For storage, I split the data by shape rather than forcing everything into one system: bulk files went to SFTP, and structured, queryable data went to PostgreSQL. To make sure this would actually run reliably on a server rather than on whoever's laptop was free, I put both services in a single Docker container, so the whole storage layer could be brought up the same way every time.

The last piece was tying it together: when a data collection session ends, the files are automatically uploaded to SFTP and the numeric data pushed to PostgreSQL, so the dashboard always has something current to read from without anyone touching it by hand.

Outcome

What shipped wasn't the AI coach the project was originally pitched as - it was the foundation that made an AI coach possible later: a working collection pipeline, a containerised storage layer, and a dashboard the next cohort could build analytics on top of instead of starting from a blank folder. That foundation is what I came back to build on top of during my graduation project, migrating this same toolkit to a properly automated deployment workflow.

The end result is a robust, scalable system that can be easily maintained and extended by future cohorts. As seen in the video below.
